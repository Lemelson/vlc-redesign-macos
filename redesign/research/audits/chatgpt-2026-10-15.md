## 6. Что сделано хорошо

Все пункты ниже [проверено] текущим исходником, если отдельно не указано runtime; это то, что следует сохранить при исправлениях.

- **Engine isolation.** Diff src/lib/include пуст; classic macOS GUI и перечисленные stock launch files не изменены. За пределами redesign/module изменены только AGENTS/CLAUDE/.github README и три разрешённых build glue файла configure.ac, modules/gui/Makefile.am, package.mak. Opt-in patches не превращены в скрытую правку engine tree.
- **Настоящие слои.** Core/protocol models, UI/Design, native adapters и plugin разделены SwiftPM targets. UI не включает VLC headers. Bridge API использует Foundation/AppKit/CoreGraphics; это не «Foundation-only», но запрет VLC headers наружу выдержан.
- **Единая композиция и geometry.** Player/panels используют общий root; right panels overlay video; top/control reveal разделены, hidden hit testing/AX отключаются. Реальный menu/Settings и fullscreen round trip дополнительно [проверено] в приложении.
- **Содержательные controls.** Default order, thick seek, cone boost, shared clock/ScrubSession и cancellation/preview cache — настоящая логика. Исправляя still pipeline, не ломать coalescing/final precise target и frame retention.
- **Связь с настоящей медиатекой.** Folder/music/history/playlist/bookmark/chapter paths трассируются до native VLC APIs, thumbnails имеют caching/invalidation. Ошибки identity/scope следует чинить внутри adapters, сохраняя асинхронные запросы.
- **Нативные службы.** NSMenu/Services/Edit responder chain, window state ownership, MediaPlayer remote commands и Now Playing реализованы. Их наличие в коде не подменяет физическую проверку медиаклавиш.
- **Schema-driven Settings.** Word choices, advanced/dependency filters, draft shortcuts/conflict handling, explicit capability ограничения и правильный reset confirmation лучше скрытого успеха неподдерживаемых действий. Исправлять semantic mappings, не возвращать неработающие строки ради количества.
- **Дизайн-система.** Tokens/fonts/Figma glyphs централизованы; Reduce Motion и accessible adjustable actions во многих местах предусмотрены. Подтверждённые contrast gaps требуют точечной доработки; композиционные AX гипотезы — отдельной runtime проверки.
- **Тестовая инфраструктура уже полезна.** Model/geometry/cancellation/contrast/interaction tests и recorded actual-engine fixtures существуют. Нужны новые regression paths и actual native host, а не только увеличение числа тестов.
- **Пределы честно документированы.** SCREENS уже различает implemented UI и acceptance; D014/D035/D036 фиксируют engine/platform limits. Эти оговорки надо сохранить в любом релизном отчёте.

### Три прежние находки, снятые из подтверждённых

[проверено] Источники и старые CUA observations сохранены; [не проверено] соответствующие пользовательские отказы. Эти записи **не входят в36 подтверждённых**, не считаются исправленными и не штрафуют как доказанные accessibility bugs.

#### CTL-04: реальная Tab-навигация меток времени не установлена

[проверено] Resting Text/onTapGesture имеет named AX actions и не имеет явного Button/button trait/focus/Return handlers; редактируемый TextField возникает после активации. [не проверено] Обычный Tab отказ: из отсутствия явного modifier нельзя строго исключить platform/gesture/AX synthesis. В v1 это было ошибочно посчитано подтверждённым product defect.

**Что решит вопрос:** Actual Tab/Return trace на обеих метках времени с системной keyboard-navigation policy; снять role/actions/focus до и после активации.

#### NAT-03: ordinary keyboard работа Queue/Bookmarks требует runtime проверки

[проверено] Нет явной row focus/arrow/Return реализации; есть .isButton, default/custom AX actions и queue onDeleteCommand. [не проверено] Отказ всех обычных platform keyboard paths: без настоящего Tab/arrow/Return trace нельзя исключить автоматическую keyboard/accessibility активацию.

**Что решит вопрос:** На Queue/Bookmarks с несколькими строками снять focus/selection/activation при Tab/arrows/Return и отдельно Full Keyboard Access; не заменять это поиском modifiers в коде.

#### NAT-06: повторяющиеся имена CUA не равны доказанным raw AX/VoiceOver именам

[проверено] CUA текстовый AX export показывает девять Accent color; источник имеет individual color labels и enclosing row label. [не проверено] Что export точно отражает сырые AXTitle/AXDescription каждого swatch, без flattening/fallback; не проверены raw attributes, речь VoiceOver и binary↔HEAD correspondence. Предыдущая причинная атрибуция override и screen-reader failure отозвана как недоказанная.

**Что решит вопрос:** Снять raw AXTitle/AXDescription/AXValue каждого swatch и VoiceOver речь, связав installed artifact с HEAD; проверить, не переименовывает ли/flatten CUA экспорт составной control.
