# 02 — Other Qt/QML forks implementing the Juxtopposed VLC redesign

Survey date: 2026-10-14. Source: `the repo root` (blobless clone, forks as remotes). Read-only: only `git merge-base`, `rev-list`, `diff --numstat`, `log` and `show` were used.

**Method.** Base = the upstream branch (`origin/master` or `origin/3.0.x`) with the nearest merge-base. "Real code" counts `git diff --numstat merge-base..branch` with these excluded: `po/`, images, fonts, SVG, `.md/.txt/.html/.json`, docs and COPYING. It is split into the Qt module (`modules/gui/qt`, without tests), engine and other modules (`src/`, `include/`, `lib/`, `modules/*` outside Qt), and tooling (CI, scripts, tests).

**Video sections** use the keyframe folder numbering in `research/video/frames/`:
01 colours/icons · 02 control bar/seek/volume · 03 top bar/fullscreen/hover · 04 subtitle+audio buttons · 05 menus/right-click · 06 subtitle import dialog · 07 player sidebar (subs/audio/video/playback) · 08 media library · 09 music · 10 network/open dialogs · 11 playlists/pins/recent/home · 12 continue watching · 13 bookmarks/chapters/OSD · 14 settings/hotkeys · 15 customization/onboarding.

**Background that matters for macOS.** All master-based forks change only the **Qt/QML interface (`modules/gui/qt`)**. On macOS, VLC 4 ships the native Cocoa interface (`modules/gui/macosx`), not Qt. So none of these forks yields a macOS redesign as-is. Qt can be built on macOS, but it is not VideoLAN's shipped path. The macOS value of these forks is their **extracted design data, specs and behaviour mapping**, not their QML.

## Per-branch notes

**Olmo-Gutierrez/redesign.** This is the most disciplined and the narrowest fork. It rebuilds only the bottom control bar against Figma at 1920 px: previous/play/next slots (30/54/30 px), Inter 15 px `HH:MM:SS`, Figma seek track and handle, a hover seek preview generated by VLC's thumbnailer (+194 lines in `player_controller.cpp`), and the cone volume with a gradient and an "audio value" box. It also adds the windowed rounded video frame. Each feature is one commit, and the README says each was checked against Figma by capture diff. The top bar, sidebar, library and settings are untouched (Phases 3–7 are still to do). The real value is `design/`, the best asset source of all the forks (see below). The `gh-pages` branch is only a 5-file landing page (`index.html`, `player.png`) with no assets.

**Green-Skeleton/redesign.** This is a shipping-oriented Windows build of VLC 4 (GitHub Actions on VideoLAN's own cross-compile image, portable zip). It is a re-skin of the stock UI: the Figma Dark/Light palette in `systempalette.cpp` with Figma style names in comments, bundled Inter, a single-row control bar, a pill play button, a thick seek bar, a sidebar card, and later a QML Settings window (`SettingsDialog/Pages/Row/Section.qml` + `settings_bridge.cpp`), an onboarding dialog and the volume wedge. Icons are regenerated with the author's `vlc-redesign-skin` tooling (`.fig` decoder), which overwrites stock `pixmaps/icons/*.svg` and `VLCIcons.ttf`. That is easy for the author but conflict-prone. It is the only fork that has merged upstream master after branching. Its README states plainly that on macOS VLC 4 uses the native UI, so the build does not apply there.

**SrDouglax/feat/m2.** This is the most process-heavy fork: milestone specs, isolated profiles, and Linux and Windows evidence. Functionally it covers a lot of M2: library grid/list/search/sort, persistent playlists, a queue separate from playlists, a tracks/playback panel with chapters and bookmarks, and persistent subtitle associations (`mlsubtitleassociations.cpp` + `SubtitleAssociationsDialog.qml` + a core hook in `src/player/medialib.c`). The big risk is that it moved the Qt module's source lists out of `Makefile.am`/`meson.build` into new `buildsystem/` include files. Every upstream Qt file addition would then need manual re-application.

*Their `.specs/` plan (Portuguese) in summary:*
- **PROJECT.md** sets the goal: a fork of VLC with the Juxtopposed UI in Qt/QML that reuses the engine and controllers, with no libVLC wrapper app. Linux first, Windows as an architectural requirement from day one. Requirements R01–R08 cover preserving playback, covering all Figma screens and states, being usable on Linux, not blocking Windows, **keeping the fork updatable (pinned base SHA, patches by responsibility, upstream-update tests)**, validating delegated work, keeping user data isolated, and keeping accessibility and l10n.
- **ROADMAP.md** defines milestones: M0 foundation (reproducible baseline, Figma matrix) → M1 first player (window, nav, controls, real video) → M2 daily use (library, playlists, tracks, subtitles, history) → M3 full coverage (music, mini player, customization, themes, onboarding, settings) → M4 Linux packaging → M5 Windows packaging. Six work fronts: A platform/CI, B visual/navigation/tokens, C player, D library, E preferences/onboarding, F verification. File ownership is exclusive per task.
- **design.md** sets the architecture: redesign QML → existing Qt controllers → existing core. Tokens are centralised in the existing style system. Keep pref IDs and semantics. Don't swap the video surface for overlays. Keep files under 500 lines. It includes a verification matrix (QML check + real capture vs Figma frame, DPI 100/150/200, X11/Wayland).
- **coverage.md / inventory.json** map **103 top-level Figma frames (57 screens + 46 component groups)** to concrete VLC symbols. Reuse codes P (playlist controller), S (MainCtx/nav), L (ML models), Q (queue), D (ML playlists), C (toolbar editor/profiles), F (prefs), A (audio effects), E (video effects), T (tracks/subs), H (hotkeys), O (first-run), N (open dialogs), X (addons), B (bookmarks), W (style/tokens). Each row carries a gap and a proof criterion.
- **video.md** distils the transcript into 16 narrative requirements V01–V16 with acceptance criteria. Examples: play stays on the left by default, the cone survives any accent colour, the queue is not a playlist, four-tab sidebar, subtitle matching per folder/playlist, per-series presets, OSD shows the bound key, onboarding stays minimal. It also lists features with **no existing engine equivalent** (seek thumbnails, draggable subtitle timeline, reverse playback, sleep timer, navigable waveform, folder pins, profile-wide settings) and open design ambiguities.
- **m1.md / m2.md / m2-visual.md / tasks.md** hold per-milestone contracts, file allow-lists, gates and measured geometry. Examples: library thumbs 316×178, radius 12, gaps 20/40, title 16.

This plan is directly reusable as a checklist for the macOS build, especially coverage.md, video.md and the "no engine equivalent" table.

**ItsAhadun/claude/magical-mccarthy-7co0gu.** This agent-authored fork has the widest QML rewrite of the stock UI. It includes a new title bar, nav pane, a 703-line mini-player card, library pages, QML menus, the player page with side panel and popups, a music player view with waveform, skip ±10/15 and other new control-bar items, a seek preview (`seek_preview.cpp`), and a full QML settings window (`dialogs/settings/*`, `settingsbackend.cpp`). It also adds an `osd-duration` core option. **design/tools contains a headless Linux Qt/QML verification harness**:
- `setup.sh` installs deps, Qt 6.8.3 via aqtinstall to match the Windows contribs, and medialibrary 0.13.2, then does a meson build plus sample media.
- `build-qt.sh` gives a ~10 s Qt plugin rebuild.
- `qml-check.sh` runs qmllint against a baseline (`qmllint-baseline.txt`) plus an import allow-list (`qml-imports-allowlist.txt`).
- `qt-packaging-check.sh` verifies only QML modules shipped by the static Windows Qt are imported. This is what caught the `QtQuick.Shapes` blank-window bug.
- `screenshot.sh` drives Xvfb + xdotool to screenshot the real app with scripted actions.
- `seed-profile.sh` creates a pre-indexed ML profile.

Its `design/SPEC.md` is the best written measurement spec of all the forks.

**stonepicaxe/redesign/figma-ui.** This fork is preferences-heavy. It has 18 new preference QML files (General, Interface, Audio, Video, Subtitles, Hotkeys, Network, Performance, Privacy, Input/Codecs, Advanced, Account, About) backed by a new generic `ConfigModel` (C++, 253 lines). It also adds Subtitle/Audio/Video drawers in the player, a frosted-glass shell, onboarding, network, new-playlist and shortcut-cheat-sheet dialogs. The control bar is a floating pill, which departs from Figma. It has a multi-OS CI matrix, but the macOS leg builds stock VLC with the Cocoa UI, so it proves nothing about the redesign on macOS. It extracted no icons.

**KoalaNalle/juxtopposed-playback-bar.** This fork has a playback bar with cone volume, a combined Queue/Bookmarks/Chapters panel (`JuxtopposedQueuePanel.qml`, a much-extended `mlbookmarkmodel.cpp`), a playback settings menu and shared navigation. **Why it touches `src/`:** while testing native seek-while-paused, the frame did not refresh and the clock drifted on resume. It changed `vlc_clock_main_reset` to keep `pause_date` while paused, forced the first decoded picture to show after a paused seek (`decoder.c`), and used the frozen pause date for lateness (`es_out.c`), with new tests. Separately it fixed Windows `vlc_pipe` name collisions between processes (`AnonPipe_N` → `VLC_<pid>_N`). These look like real upstream bugs, but they violate "engine untouched". If they matter, they should go upstream, not into a redesign fork. Its attribution file confirms the Figma community file is **CC BY 4.0**.

**Geckostya/redesign/stage1.** This fork builds a parallel interface instead of editing the stock one. `modules/gui/qt/redesign/` is a self-contained `VLC.Redesign` QML module (`RMainInterface.qml` root, `Theme.qml` tokens, about 100 components). C++ bridges (`redesign_settings`, `redesign_effects`, `redesign_icon_provider`) sit over existing controllers. The only hook into upstream code is `mainui.cpp`, which picks `RMainInterface.qml` when `qt-redesign` is set, plus registrations and qrc/manifest entries. Only 13 upstream lines were deleted. Coverage is the broadest of all master forks: an acceptance doc reports 72/72 integration checks on Windows, 13 settings categories and profiles. Polish varies, and the Light theme does not match Figma. Architecturally this is the model to copy: an additive layer that rebases cleanly.

**ExPikaPaka/redesign/08-volume-wedge.** This fork is a tidy stack of eight small branches: tokens → type/metrics → toggle → inputs → top bar → control bar → single-row controls → volume wedge. Each is a focused, well-explained in-place theme change. **The huge `po/` deletions are accidental.** They all sit in commit `195f3898cb`, whose message is only about the top bar. They are gettext re-wrap/merge output from a build step (only line wrapping and obsolete entries changed). Drop them if this branch is reused.

**ldl1949/redesign-phase2.** It contains phase 1 (player UI) and phase 2 (subtitle and playback tools): a sidebar (1,002 lines) with presets and a sleep timer, a tracks popup, an add-subtitles dialog with match picking, a subtitle timeline fed by a GUI-side cue parser (`subtitle_helper.cpp`), and bookmarks. Section 13 ("OSD shows the key you pressed") is implemented by modifying `modules/control/hotkeys.c`, which is outside the GUI. It extracted no Figma assets.

**webmaster94/redesign (3.0.x).** "Reframe" is a fully rebranded Windows product on VLC 3.0.24's **Qt Widgets** UI. It has about 8k lines of hand-written C++ widgets covering every section, plus native OpenSubtitles login/download, an NSIS installer and an IPC/profile identity separate from stock VLC. It touches `src/` (osd-timeout, renamed Windows dirs/mutex), freetype, libass and the visualizer, and relicenses the combined work to GPL-3.0-or-later. Its icons are hand-drawn. **Compared with origin/3.0.x:** it is based on `6de05adc` (2026-09-17), and origin/3.0.x has moved 30 commits since. Not useful for VLC 4 or macOS beyond its `doc/redesign/design-inventory.md` and licensing notes.

**lin-ycv/windows-figma-vlc-3.0.24.** This is a Windows-only Qt stylesheet with approximate dark colours and a wider playlist splitter, all `#ifdef Q_OS_WIN`. It is a token gesture, not a redesign.

**mholtzhausen / anthonyliot / TheFenrisLycaon.**
- mholtzhausen has **docs only**. `docs/moth-ui-plan.md` is a coherent 11-phase plan with node ids and tokens, which is relevant as a reference.
- anthonyliot is **not a redesign** but is relevant to macOS: a `VLCDisplayLink` (CADisplayLink on 14+) for the native macOS interface.
- TheFenrisLycaon is **not a redesign**: a tree-wide VLC→Heimdall rename plus pre-redesign Qt behaviour tests.

## Best source of Figma-extracted assets (for a macOS build)

Ranked. All forks extracted from personal duplicates of community file 1691465999134370980; file keys differ, e.g. `B7ifd32zHbliiZs9q00JG3` (Olmo), `fQSxoEi1zmnD5fQacw0qGs` (SrDouglax), `E17x5esiisVGqtS4CB4Hh2` (ItsAhadun), `Ewti3Do8MQbCKzyDbAZWC2` (mholtzhausen). **Node ids are consistent across copies** (e.g. Icon set `42:356`, Player `187:328`, Volume `244:184`), so references can be cross-checked between forks.

## Verdict

- **No fork gives a macOS redesign.** Every serious effort targets VLC 4's Qt/QML UI, which VideoLAN does not ship on macOS. The two 3.0.x forks target VLC 3's Qt Widgets UI, a dead end. The only `modules/gui/macosx` work (anthonyliot) is unrelated plumbing.
- **Most reusable structure:** Geckostya's additive `modules/gui/qt/redesign/` layer behind a `--qt-redesign` switch (13 upstream lines deleted, no core changes). It is the pattern that survives upstream pulls, and the same principle should guide a macOS implementation: a separate layer over the unchanged engine and controllers.
- **Branches to avoid as a base:**
  - In-place rewrites that conflict with upstream: ItsAhadun, SrDouglax's build-system refactor, Green-Skeleton's icon/font overwrite.
  - Anything that edits `src/`: KoalaNalle, ItsAhadun, SrDouglax, webmaster94; ldl1949 edits `modules/control`.
  - ExPikaPaka's accidental po churn (revert before reuse).
- **Take the data, not the QML:**
  - Olmo's icons and tokens (already in `research/figma/`).
  - ItsAhadun's `SPEC.md` measurements.
  - SrDouglax's coverage matrix and V01–V16 behaviour spec as the feature checklist.
  - The SrDouglax/KoalaNalle volume and queue SVGs.
  - ItsAhadun's `design/tools` harness as inspiration for a screenshot-vs-Figma verification loop.
