# Decision log

Short records of decisions that shape the project. Newest at the bottom. To change
a decision, add a new entry that supersedes the old one rather than editing history.
Status: **accepted**, **provisional** (works for now, owner to confirm), **open**.

---

### D001 — Build our own macOS interface instead of porting a community fork · accepted · 2026-10-14
All ~20 community implementations target VLC 4's Qt/QML interface (Windows/Linux)
or are standalone Windows/Linux apps. None runs as a native Mac app. We build
a native macOS interface from scratch and use the forks as references
(`research/FORKS.md`).

### D002 — Architecture: a new in-tree interface module · accepted · 2026-10-14
Option D in `research/analysis/04-macos-architecture.md`: `modules/gui/macosx_redesign/`
inside this VLC fork, with full access to VLC's internal player, playlist,
media library, configuration, hotkeys, dialogs and extensions.
Rejected alternatives:
- (A) Editing `modules/gui/macosx`: upstream's busiest area, heading in a different design direction, so merge conflicts would never end.
- (B) Qt on macOS: unsupported by VideoLAN and not native.
- (C) A separate VLCKit app: libvlc exposes no configuration, media library, hotkeys or extensions, so the settings screen would be impossible, and VLCKit 4 is still alpha.

### D003 — Swift, SwiftUI and AppKit, with a thin C/Objective-C bridge · accepted · 2026-10-14
SwiftUI for views. AppKit for window chrome, the video host view, menus and
performance-critical lists. A bridge layer owns all VLC callbacks and exposes
Swift-friendly models. The UI depends only on protocols, so it runs against a
mock backend (previews and a gallery app) without building VLC.

### D004 — The engine is not modified · accepted · 2026-10-14
No changes to `src/`, `lib/`, `include/` or other modules except build and
packaging glue. Exceptions need a new decision entry explaining why the
interface layer can't do it, and must be small, isolated and upstreamable.

### D005 — Repository model · accepted · 2026-10-14
This repo is a fork of `videolan/vlc` with full history. `main` = upstream master
+ our commits. The base is tagged `upstream-base-2026-10-14` (upstream `4ca4eb0c3e`).
We **merge** `upstream/master` regularly; we never rebase published history. All our
material lives in `redesign/` and `modules/gui/macosx_redesign/`. The GitHub landing page is
`.github/README.md`, so upstream's `README.md` stays untouched.

### D006 — Sources of truth · accepted · 2026-10-14
Visuals: the Figma file. Behavior and intent: the video. Semantics: VLC. See
`PHILOSOPHY.md` §1. Values sampled from video frames are never used where a
Figma value exists.

### D007 — Native window chrome · provisional · 2026-10-14
The Figma design shows Windows-style minimize/maximize/close buttons on the top right.
On macOS we use the standard traffic lights (left), keep the rest of the Figma top bar
(menu, sidebar toggle, current folder/show title, centered title), and keep
fullscreen and Picture-in-Picture as Figma-styled buttons on the top right, where
the design puts them. The app has a real macOS menu bar, which mirrors the
in-window `⋯` menu.
*Amended (D055, 2026-10-17):* the default top bar keeps only the fullscreen button on the right
(247:464 minus the Windows controls). Picture in Picture is a customisable control-bar item and
Video › Picture in Picture; it is not in the default top bar.

### D008 — Liquid Glass · provisional · 2026-10-14
Default appearance is the flat Figma look. Surfaces Figma marks as translucent
(`BG/* Transparent` styles, background blur 50) use native materials. On macOS 26+
they may use the system glass effect if it looks like the design. A full
"Glass" appearance option may come later as an extra theme, never replacing the Figma look.

### D009 — Copyrighted material stays local · accepted · 2026-10-14
The video, its frames and its transcript are Juxtopposed's copyrighted work. They
live in `../reference/` (outside the repo), regenerated by
`redesign/tools/fetch-reference.sh`, and are never committed. Figma renders and data
are committed under CC BY 4.0 with attribution.

### D010 — Name and branding · provisional · 2026-10-14
Repository and docs describe the project as an *unofficial fork of VLC* (descriptive use).
Local/dev builds are called **VLC Redesign** and keep the cone, as the design requires.
Before any public binary: check VideoLAN's trademark terms; if a modified build may not carry
the "VLC" name, ship under a close alternative (proposal: **Cone Player**) with an original
cone-inspired icon, and keep "based on VLC" in the About box. Owner leans to keeping "VLC".

### D011 — Minimum macOS version · accepted · 2026-10-14
macOS 14 Sonoma or newer (SwiftUI Observation, modern AppKit/SwiftUI interop),
with Liquid Glass gated to macOS 26+. Applies to our plugin and the app; the engine keeps
upstream's own minimum (10.13). Confirmed in `ARCHITECTURE.md`.

### D012 — Distribution · accepted · 2026-10-14
GPL-2.0-or-later like VLC. Sources public. Signed and notarized DMG with our own Developer
ID, bundle id and update feed (not VideoLAN's). No Mac App Store (GPL).

### D013 — Settings through a mapping file · accepted · 2026-10-14
The 13-category settings UI (General, Interface, Privacy, Controls, Playback, Video, Audio, Subtitles, Library, Network, Performance, Recording, Extensions) is driven by a checked-in mapping (Figma row → VLC
option name, control type, category, basic/advanced). A check fails when upstream adds or
renames options that are not mapped, so upstream changes surface as tasks, not bugs.
Seed data: dsojevic's catalog and nagasab's `prefs.py`.

### D014 — Interface features and engine limits · partially resolved · 2026-10-14
- Reverse playback is not supported by this engine (`input.c` clamps rates to a positive
  minimum). The Playback tab still lists it, because it is in the designed row list (09m17.5):
  the toggle is shown OFF and disabled, with an ⓘ tooltip saying why (polish pass, G-panels).
- Waveforms are implemented by a cancellable AVFoundation analysis pass for readable local
  audio with a finite duration. WAV and AAC are verified; unsupported sources return no waveform.
- Subtitle cues are parsed in the interface layer for the timeline. Loading and changing media
  cancels stale work; embedded subtitle formats without an exposed cue source remain unavailable.
- OpenSubtitles requires a configured API key or proxy. The native backend marks online search
  unavailable; local subtitle import and matching remain functional.
See `research/from-forks/floklein-research/playback-feasibility-*.md`.

### D016 — Our interface replaces the stock one at build time · accepted · 2026-10-14
The stock macOS GUI and ours cannot be installed together: both provide a video
window, and we compile some upstream model classes. Our build uses `--disable-macosx`
and ships only `macosx_redesign`. Our app uses its own bundle id, so its preferences,
media library and caches are separate from an installed stock VLC. See
`ARCHITECTURE.md` for the 3 upstream files touched (~8 lines).

### D017 — Publishing happens at the end · accepted · 2026-10-14
No GitHub repository, announcement or upstream discussion until there is a working build worth
showing (end of P1 at the earliest). The owner approves each outward step. Until then
everything stays local.

### D019 — Adapt canonical window geometry to smaller Mac windows · accepted · 2026-10-14

40-point top bar and control bar span the window; the full library replaces the video canvas
and uses the same retained video surface in its draggable mini player. Native traffic lights
follow D007. These responsive choices cover behavior not specified by the fixed-size Figma.

### D020 — Scoped paused-seek engine correction · accepted in isolated Codex branch · 2026-10-14
The owner's completion request includes working playback controls. Independent actual
software-decoder and native VideoToolbox/samplebufferdisplay probes reproduced a paused
seek failure before the new interface receives a frame: the first target picture has
`b_first=1`, `b_waiting=0`, `b_force=0` after buffering, and is dropped as late. The
native interface issues the correct precise seek. A NextVideoFrame workaround displays
the target but fails subsequent resume and clean shutdown, so it must not ship.

This records the narrow exception required by AGENTS.md before changing upstream engine
code: investigate and validate only the first-frame force condition in
`src/input/decoder.c` in the isolated Codex branch/build. Preserve the Claude checkpoint,
its original sources, and stock `build/arm64`. No other engine edits are authorized by
this decision. Integrate only with target-picture PTS evidence for paused absolute,
relative and positional seeks, sustained pause, normal resume/playing seek, and clean
stop/shutdown in both software and the actual Apple pipeline. Until those checks pass,
the exception remains an experiment and no corrected engine is accepted or packaged.
Evidence: `../build/` copies of `/private/tmp/mxr-paused-seek-proof/`.

D020 experiment extension (2026-10-14): source and read-only LLDB also confirm
that paused PCR updates use current wall time while the input-clock origin is anchored
at `i_pause_date`. A two-second ordinary pause produced a 1,005,561 µs late-PCR result,
reset buffering and advanced past the requested target. Extend the isolated experiment
only to the PCR `system_now` condition in `src/input/es_out.c`: use `EsOutIsPaused`
(user pause or existing rebuffering) rather than rebuffering alone. The existing pause
anchor/locking/rate logic stays intact. `src/video_output/video_output.c`, player timer,
and all other engine paths remain read-only. Both changes must meet the complete D020
runtime contract together before integration; a source review is not runtime acceptance.

D020 experiment extension (2026-10-14): the two-path candidate displays all
paused targets correctly, but actual software and Apple A/V probes still fail normal
resume. Matching C85BAE76 core LLDB evidence shows `vlc_clock_main_reset` clears
`pause_date` while `main_clock->paused` remains true. After an 8.926620-second pause,
`vlc_clock_main_ChangePause(false)` therefore returns before shifting the first-PCR
and synchronization anchors. Extend the experiment only to the pause-date reset
condition in `src/clock/clock.c`: retain the existing pause anchor while paused,
including Reset and SetFirstPcr; retain the existing unpaused reset behavior and lock.
Add a pause/reset/resume regression in the redesign tooling or an external harness.
No other engine paths are authorized. All three changes must pass the original D020
contract together, including sustained normal resume, audio/video synchronization,
subsequent playing seeks, and clean stop, before integration or packaging. Evidence:
`/private/tmp/mxr-paused-seek-proof/apple-clock-v2-debug.log` (later copied to build).

D020 experiment extension (2026-10-14): the three-path candidate passes the
public-clock regression and software/AUHAL playback, but VideoToolbox/AUHAL
resume remains blocked. Matching 9FF95376 core LLDB captures the video decoder
inside `pic_pacer_WaitAllocatableSlot` with 16 allocated fields, `paused=0`,
`output_paused=1` and `frames_countdown=0`. The paused vout holds the pictures;
the blocked decoder cannot reach its existing output-resume loop to release them.
Extend only `src/input/decoder.c` to apply the existing video output-resume helper
synchronously in ChangePause(false), under the existing FIFO lock and guarded by
the video category and paused output. Preserve the normal decoder-loop date
acknowledgement, unchanged pause/audio/SPU behavior, and existing vout lifetime and
FIFO/control lock order; document this guarded input-thread access. Do not flush
or discard decoded pictures. No fourth engine path is authorized. This remains an
experiment pending the complete D020 runtime contract, particularly actual
VideoToolbox/AUHAL sustained resume and clean stop. Evidence:
`/private/tmp/mxr-paused-seek-proof/resume-pacer-debug.log` (later copied to build).

D020 experiment extension (2026-10-14): v4 passes software and Apple video
playback, including silent video, but the same audio-only WAV seek/resume test
passes on the original core and fails on v4. AUHAL schedules the first resumed

No master update, timer, audio-output, vout or other engine path is authorized.
Add late-reference regression controls and require the full original D020
contract plus audio-only AUHAL seek/resume before acceptance. Evidence:
`../build/logs/codex-clock-pause-reset-v4-before.log`,
`/private/tmp/mxr-clock-reset-review/v4-late-reference.log`, and

## Claude polish pass (branch `claude/polish`, on top of `codex/native-redesign`)

Based on the 8-area review of 2026-10-14 (219 verified findings; summary in

### D021 — One window composition, panels overlay the video · accepted · 2026-10-14
The real window must equal the design composition. One persistent view tree for player,
library and panels (no swapping the whole tree when a panel opens). The track popover is
anchored bottom-right, 20 pt from the video's right edge and 20 pt above the control bar
(Theme.Metric.SidePanels.placement), as in the video at 04m42–06m21. The 4-tab sidebar and
the queue **float over the video** (top-right, 20 pt insets, width min(400, available)); they
never push or shrink the video. Supersedes any push/HStack layout.

### D022 — Single 40 pt top bar with traffic lights · accepted · 2026-10-14
The content ignores the titlebar safe area; the top bar starts at y = 0. Traffic lights are
vertically centred in the 40 pt bar; the cone follows them with the Figma gap (reserve derived
from the zoom button frame, 0 in fullscreen/Hide UI). The top bar is a drag region;
double-click follows the system titlebar double-click preference. Traffic lights hide with
the bars (Hide UI, auto-hidden bars) and reappear with the top bar.

### D023 — Bars reveal independently · accepted · 2026-10-14
Top bar and control bar have separate visibility, driven by their own hot zones and hide
timers; a bar stays while the pointer is over it or one of its popups is open. Hide is
immediate after leaving (short fade, Reduce Motion respected). Cursor hides over fullscreen
video when bars are hidden.
Clarification (2026-10-15): "immediate" means no delay beyond the Settings "Hide after" value,
whose default stays 0.5 s because Figma Settings – Interface (3046:10057) shows the slider there

### D024 — Motion and dismissal are uniform · accepted · 2026-10-14
Every popup (⋯ menu, submenus, track popover, sidebar, queue, dropdowns, context menus)
uses one presentation: fade + 6 pt slide from its anchor, 0.15 s ease-out in, 0.1 s out,
none under Reduce Motion. All close on Esc and on click outside; a click outside that closes a
popup does not also toggle play/pause. No NSPopover arrows anywhere.

### D025 — Menus and dropdowns are Figma cards · accepted · 2026-10-14
One design-system popup menu (borderless panel, Figma `menu`/`context menu`/`Dropdown`
styles: rows 48 pt, two-tone icons, shortcut column, orange ✓, hover row) used by the ⋯ menu
and its submenus (hover-open), the right-click menu, library row/folder/playlist menus,
sidebar and settings dropdowns. The native NSMenu is used only for the macOS menu bar.

### D037 — Engine configuration is authoritative at startup · accepted · 2026-10-15
Connecting ProfileStore does not apply settings to the engine or save VLC's
configuration. It does refresh the active profile's own JSON snapshot. VLC can persist options
outside our settings adapter (for example auhal volume), so replaying a stale full
schema snapshot on launch loses user state. An explicit profile selection applies
only `SettingsCatalog.referencedOptions`; legacy app shortcut defaults are excluded.
Migration preserves profile identities, names and layouts while dropping unrelated
engine options. This does not promise recovery of values overwritten by older builds.

Presets distinguish an uncaptured section from an explicit Automatic/reset value.
New captures preserve that distinction. Old ambiguous payloads use conservative
inference; a historical nil alone cannot prove what the user intended. Playback is
not added to presets: D033 and Figma take precedence over the old all-four-tabs
summary in VIDEO_BREAKDOWN.
