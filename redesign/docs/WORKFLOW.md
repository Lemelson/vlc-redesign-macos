# Workflow for humans and agents

The project is designed so that many agents can work in parallel. Each takes one
screen or component, iterates until it matches the design, and hands it to a
verifier.

## Units of work

- **Screens**: `S01…` in `redesign/design/SCREENS.md`. Each has Figma node ids, renders,
  spec section, video frames and the VLC functionality it needs.
- **Components**: tokens, icons, buttons, toggles, sliders, menus, panels. They are built
  first, in the design system, and reused by every screen.
- **Phases**: see `PLAN.md`. Don't start a screen whose components don't exist yet.
  Build the component first.

`SCREENS.md` is generated by `redesign/tools/figma/gen_screens.py` (rows, status
preamble and the `Parity · live` column, computed from the latest parity judges' JSON plus
the live notes in the script). Never edit it by hand: change the generator and rerun it;
`modules/gui/macosx_redesign/tools/test-screens-doc.py` fails when the file and the
generator disagree. Claim a unit in the PR description or the wave's workflow script.

## Branches and worktrees

- One branch per unit: `ui/S07-control-bar`, `ds/slider`, `core/player-bridge`.
- Use `git worktree add ../wt-S07 -b ui/S07-control-bar main` so parallel agents
  don't share a working tree.
- Commit messages follow VLC style with our prefix: `macosx_redesign: add seek bar thumbnails`
  or `redesign/docs: …`. The body says *why* and references `S07` / `D013` / spec section.
- Merge into `main` only after verification (below).

## The loop for every screen or component

1. **Read.** The `SCREENS.md` row, then:
   - the spec section (`design/spec/`);
   - the video breakdown section with its key frames (`docs/design/VIDEO_BREAKDOWN.md`);
   - the Figma render(s) and node data (`design/figma/INDEX.md`, `figma_file.json`);
   - the tokens (`design/tokens/`).
2. **Build against the mock backend.** Implement in the design system / UI target, and
   render it in the gallery app or an Xcode Preview with realistic mock data. No
   VLC build is needed for this step.
3. **Compare to Figma.** Every entry is checked against the crop of its Figma node with
   `mxr-snapshot` (CLI) and the Gallery app, both in `modules/gui/macosx_redesign`.
   - **Make the entry comparable.** In its `GalleryEntry` (one provider file per component
     or screen under `Sources/MXRGalleryCatalog/Entries/`), set `figmaNode` to the exact
     node whose box equals `size`, usually a variant inside a component set (`848:1711`
     "type=play", not the set `848:1712`). If the node sits on a surface in its frame
     (not in a transparent component set), set `background:` to that surface's token.
     Entries with AppKit-backed views or materials need `renderEngine: .hostingView`.
   - **Find node ids and run the check:**

     ```sh
     cd modules/gui/macosx_redesign
     swift run mxr-snapshot find "Show Advanced" --frame 491:1780   # names and text → node ids
     swift run mxr-snapshot node 848:1712                            # frame, render file, crop, children
     swift run mxr-snapshot check --id X.PlayDemo/play               # render + Figma crop + compare
     swift run mxr-snapshot check --id C.SeekBar/hover --scheme light --accent red
     swift run mxr-snapshot check --all                              # every entry with a figmaNode
     swift run MXRGallery --entry X.PlayDemo/play --mode overlay     # interactive comparison
     ```

     `X.PlayDemo/play` is a tooling demo (a token-built stand-in for node 848:1711) that
     goes away once `C.PlayButton` exists; use any `C.*` entry with a `figmaNode` instead.
     `check` writes `render.png`, `ref.png`, `side-by-side.png`, `overlay-50.png`,
     `diff-heatmap.png` and `report.txt` to `.build/mxr-tools/snapshots/<id>/`. The
     lower-level commands are `render --id`, `ref --node … --out ref.png` and
     `compare a.png b.png --out <dir>`; `swift run mxr-snapshot help` lists every option.
     Without a Swift build, `python3 -I redesign/tools/figma/figma_ref.py <node>` crops
     the same reference with the same math and rounding: the node box minus the frame's
     render-bounds origin, times the export scale 2 (every render is
     `ceil(render bounds × 2)` px with pixel 0 at the render-bounds origin). Crops at 2×
     agree with `mxr-snapshot` within a level or two per channel.
   - **Crop notes.** Some frames (Onboarding, Components, Designs) have render bounds
     that start between pixels (x.2 / y.8), and some nodes sit at half points. Their
     crops are shifted bilinearly so the node starts exactly at the crop's corner;
     `ref`/`check` say so ("starts between pixels"), and edges are slightly softer than
     in the render, which the structural test tolerates. `--scale 1` area-averages the
     2× render. A "hidden" warning means the node or one of its parents is hidden in
     Figma, so the render doesn't show it: pick a visible node.
   - **Gallery app.** Sidebar by kind (D/C/S/X); canvas at 1:1 with zoom (⌘+ / ⌘− / ⌘0);
     modes ⌘1–⌘6: SwiftUI only, side by side, overlay (opacity slider), difference
     (identical pixels turn black), Figma only, heat map; ⇧⌘M measures like `check`,
     ⇧⌘S saves the same files (measuring again first if the scheme or accent changed);
     measuring runs in the background. Color scheme and accent pickers in the toolbar. The
     inspector shows the node, frame, render file and crop. `--snapshot-window out.png`
     writes the Gallery window to a PNG and quits (no screen-recording permission needed).
   - **Read the result.** Pixels are compared as premultiplied sRGB; a pixel's delta is
     its largest channel difference.

     | Metric | Meaning | FAIL | REVIEW |
     |---|---|---|---|
     | size | render vs crop in pixels | any mismatch | |
     | strict Δ > 24 | differs by > 24/255; includes antialiasing. "Δ area" boxes the largest connected patch of them | (informational) | |
     | structural | still differs when each pixel may match anything within ½ pt in the other image: missing, extra, moved (≥ 1 pt) or reshaped content, wrong font | > 2 % | > 0.5 % |
     | flat color | both images locally solid but colors differ by ≥ 2/255: wrong token or opacity, or a filled shape missing/extra. Neighbouring dark surface tokens are only 2–5 apart (`bgA3` #1B1B1B vs `bgA4` #191919), so even a "barely visible" difference is a wrong token | > 1 % | > 0.1 % |
     | regions | connected structural/flat-color areas, boxed in the heat map; a region with flat-color pixels lists its dominant colors, e.g. `render #1F1F1F (dark bgA2) vs Figma #1B1B1B (dark bgA3), Δ 4` | one ≥ 400 pt² | one ≥ 16 pt² |
     | offset | "matches better moved +1, 0 pt": move the content by that much | | |

     PASS means no visible difference. A REVIEW is acceptable only when every boxed region
     is explained (for example a quirk in the Figma file; note it in `NOTES.md` or the PR).
     For a flat-color FAIL, read the colors line: two token names mean the wrong token;
     a Figma color that matches no token usually means a translucent token or a shadow
     composited on the surface, so check the opacity and the layers under it. Deltas
     of 1 are rasterization noise and never count.
     The heat map shows a dimmed copy of the render: blue = small deltas, yellow =
     antialiasing only (ignore), red = structural, magenta = flat-color, cyan boxes = regions.
   - **Text.** The tools draw text without Core Text font smoothing, which otherwise adds
     about 30 % ink to light text that Figma's rasterizer doesn't. Glyph edges still
     differ slightly (yellow in the heat map); that is acceptable. Red on glyphs means a
     wrong font, weight, size or position. Add `--font-smoothing` to see macOS's default.
   - **Limits.** Figma background blur blurs whatever was behind the node, so blurred
     panels match only when the entry draws the same backdrop. Video frames and cover art
     in Figma frames need the same mock image to compare. Don't chase offsets under ½ pt.
   - `swift test` runs `MXRUISnapshotTests`: every entry renders at its size, ids are
     well formed, every `figmaNode` exists with the entry's size, and the crop math and
     verdict thresholds behave as described here.
4. **States.** Hover, pressed, focused, disabled, selected, empty, loading, error, light
   theme, accent colors. Where Figma doesn't show a state, follow `PHILOSOPHY.md` §4
   and record it in `DECISIONS.md` if it's a new pattern.
5. **Wire to VLC.** Connect it to the real bridge. Run VLC.app with our interface
   (`BUILD.md`) and real media: a long video, a series folder with subtitles, music
   with cover art, a network stream.
6. **Performance.** Watch CPU with the player idle and while hovering or seeking in
   Activity Monitor or Instruments. No dropped frames during overlay animations.
7. **Accessibility.** Labels for every control, keyboard reachability, VoiceOver
   order, reduced motion.
8. **Hand off to a verifier.** A different agent (not the author) re-runs steps 3–7
   against the checklist and either approves or files concrete issues.
9. **Mark done**: rerun `gen_screens.py` with the new parity results (`--parity`) or live
   notes. Add a gallery screenshot to the PR description.

## Rules

- **Tokens only.** No literal colors, font sizes, radii or spacings in views; everything
  comes from `Theme` (generated from `design/tokens/`). If a value is missing,
  add it to the tokens with its Figma source.
- **Icons from the asset catalog** (generated from `design/figma/icons-svg/`). Never
  substitute SF Symbols for a Figma icon. SF Symbols are allowed only for native macOS
  affordances the design doesn't cover.
- **Never edit upstream code** outside the short list in `ARCHITECTURE.md`. If you think
  you must, stop and write a `DECISIONS.md` proposal.
- **Don't guess behavior silently.** If the video, Figma and the principles don't
  answer it, add an open question in `DECISIONS.md` and pick the most
  conservative option.
- **Look at other forks when stuck.** `research/FORKS.md` tells you which fork solved
  what (e.g. Geckostya and Pyr0zen for library flows, dsojevic for settings). Re-express
  the idea natively; don't port QML.
- **Keep docs current.** If you learn something non-obvious (VLC API quirk, build
  trick), add it to `docs/NOTES.md`.

## Keeping up with upstream

Weekly, or before a release:

```sh
git fetch upstream
git merge upstream/master        # conflicts should only ever be in our few touched files
# build, run the smoke checklist in BUILD.md, then push
```

If a merge conflicts outside the files listed in `ARCHITECTURE.md`, our isolation
broke. Fix that first.

## Definition of done (screen)

- [ ] Matches the Figma render at normal viewing distance (diff image attached).
- [ ] All states implemented; undocumented ones recorded in `DECISIONS.md`.
- [ ] Works with real VLC in VLC.app; no regressions in playback.
- [ ] No CPU or frame-rate regressions.
- [ ] Accessible (labels, keyboard, VoiceOver).
- [ ] `SCREENS.md` regenerated (`gen_screens.py --check` passes); verifier approved.

## Checks

`$BUILD` is the configured engine build directory (see `BUILD.md`). The Makefile is
the single list of gates; do not copy its recipe here.

```sh
make -C "$BUILD/modules" check-macosx-redesign      # generators --check, native contracts,
                                                    # all Swift tests, tooling tests
```

For a quick loop on part of it, from `modules/gui/macosx_redesign`:

```sh
swift test --filter <Suite>                                  # targeted Swift tests while iterating
python3 tools/run-swift-tests.py . "$SCRATCH/swift-check"     # the full Swift gate (fresh scratch dir)
python3 tools/native-tests.py --engine-build "$BUILD"        # default native contracts (+ --suite ...)
```

`run-swift-tests.py` compares discovered XCTest names with executed results and fails
on a missing, skipped or failed case. Tests must not call `finishLaunching`, activate
the test process, or order a test window onscreen. Offscreen AppKit/AX contracts are
separate from actual VoiceOver and keyboard acceptance.

Default native contracts exercise schema/parsers and isolated lifetime/sort/input
policies; `native-tests.py` removes its temporary work directory after a pass and
keeps it (path printed) on failure or with `--keep`. A harness that misses a deadline
prints its running phase, the last engine log line and a `sample` call graph into that
directory (`BUILD.md` §1, test details). Explicit runtime gates, not part
of `check`, each with its own prerequisites and isolation:

```sh
make -C "$BUILD/modules" check-macosx-redesign-library
make -C "$BUILD/modules" check-macosx-redesign-audio
make -C "$BUILD/modules" check-macosx-redesign-media
make -C "$BUILD/modules" check-macosx-redesign-extensions
make -C "$BUILD/modules" check-macosx-redesign-subtitle-runtime
```

`--suite build-runtime` only compiles/links the runtime harnesses; a compile-only PASS
is never a playback/output PASS.

After `tools/install-app.sh`, with the app closed, run the installed-app gate: a real
start/play/quit with the redesign interface and video surface, VideoToolbox, auhal,
subtitles when an `.srt` sits next to the media, a clean exit and no "stale plugins
cache" line (the log is written to `$BUILD/modules/macosx-redesign-smoke.log`):

```sh
make -C "$BUILD/modules" check-macosx-redesign-app \
    MXR_SMOKE_MEDIA='"/path/to/clip 1.mp4" "/path/to/clip 2.mp4"'
```

Actual app verification uses only `/Applications/VLC Redesign.app`
(`org.example.vlc-redesign.codex`), never the owner's stock VLC. Acquire the shared
lock (`redesign/research/final-polish/workflows/lock.sh acquire <who>`, directory from
`MXR_LOCK_DIR`; the same lock serializes native `make`, native suites and installs),
wait for at least 120 s HID idle before mouse/keyboard (`wait-idle.sh`),
and stop input if the owner returns or the app loses foreground. Close the app
and release the lock afterward. Record the source/binary identity, real-window
screenshots, visible/hidden CPU samples and user-data effects separately from
gallery evidence. The current repair ledger is
`redesign/research/AUDIT_FIXES_2026-10-15.md`; historical audit scores are unchanged.
